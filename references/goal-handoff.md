# Goal 启动与执行交接

准备操作真实 Goal 时读取；创建新 Goal 要先有可执行计划，处理用户对现有 Goal 的暂停请求则不必等待新计划。以下流程服从当前环境实际提供的工具定义；产品版本间的状态名称、暂停方式和预算控制可能不同。

## 将计划压缩为目标合同

将用户确认的结果、验收、边界和阻塞条件写入 objective。保留决定成败的信息，不复制全部对话、探索日志或项目规范。不加入新的成功标准，也不丢弃已经接受的必要条件。

```text
完成【具体结果】，由【验收证据】验证，保持【必要约束】。
范围为【相关模块、材料和允许动作】，遵循适用项目规范。
从【有证据支持的第一步】开始；每轮依据新增证据选择下一步，
复用仍有效的检查结果，最终完成适用的验证门槛。
若【明确的外部阻塞或无可行路径】，报告已验证事实、尝试路径和所需输入。
交付【产物及验证摘要】；所有验收条件满足后结束。
```

目标应足以独立识别完成条件。长计划可引用已存在的确定位置，但核心验收条件应保留在 objective 中。只要求写计划或生成 `/goal` 文本时，到此交付，不创建 Goal。

## 检查执行模式与能力

- 检查当前协作模式是否允许实施。仅规划模式中继续完善或交付计划，不创建或恢复执行 Goal，不开始实现；说明当前客户端所需的模式切换。不能通过口头宣布或 shell 命令把自己切换到执行模式。
- 切换后保留已确认计划和既有授权，只核对发生变化的条件，不重做采访或重复索要同一授权。用户明确要求暂停现有 Goal 时，按实际工具能力处理暂停，不受“准备启动”的步骤限制。
- 检查 Goal 查询、创建及更新能力。若使用 `get_goal`、`create_goal`、`update_goal` 等名称，按当前参数契约调用；工具名本身不代表它支持改写 objective 或切换所有状态。

没有真实 Goal 能力时，交付可复制到支持客户端的 `/goal …` 文本，并说明尚未启动。`/goal` 是客户端命令，不是 shell 命令。不要编造后台循环、定时任务或自制替代机制；用户另行授权普通执行时可按普通任务继续，并明确执行方式。

## 核对持久化目标并启动

1. 查询当前 Goal，确定应创建、复用还是调整。不得把未完成目标标为完成来腾出位置。
2. 操作前确定预算参数。仅在用户明确指定数字 token 预算时传入；创建时未指定则省略，“省 token”不代表默认数值。调整已有 Goal 时保留未被用户要求改变的预算；不能设置时说明限制。
3. 若已有本任务的活动 Goal，逐项比较其结果、验收和范围是否与最新获授权计划一致。语义等价时沿用目标和用量记录，纯措辞变化不需要重写。
4. 同一任务的验收或范围若有实质变化，用当前支持的接口同步，再核对返回状态。接口无法改写目标时，交付新目标文本并说明所需用户操作；不能只更新对话计划，就让旧目标按不同标准继续。目标更新可能重置用量，按实际返回说明影响，不通过重建目标绕过预算。
5. 其他未完成、暂停、受预算限制或阻塞的 Goal，不静默清除、覆盖或恢复。结合已获授权和实际工具能力处理，能力不足时说明所需操作；这不要求用户重复批准已经确定的任务。
6. 没有目标或先前目标已完成时，使用准备好的 objective 和预算参数创建。创建、调整或复用后，确认实际目标和状态与计划一致，核对已指定的预算，再执行下一项未完成的实质步骤。操作失败时报告具体原因，不能声称 Goal 已启动或已同步。

## 持续执行和停止

- 复用已有有效证据，按需取得基线或最小复现，再完成实现和验证。续跑时从未完成步骤继续；阶段顺序可随证据调整，结果和约束保持一致。
- 每轮先做聚焦验证，最终满足适用的项目验证门槛。已通过的检查在相关代码和环境不变时复用；同条件下的失败尝试没有新证据就不重复。连续无进展时复盘策略。
- 在重要阶段或预算判断需要时读取进度，避免高频查询 Goal 状态。完成后报告实际可获得的用量，不估造统计。
- 按当前工具契约更新状态。只有验收证据全部支持目标且没有必要工作剩余时才标记完成。未完成、环境受限、预算不足分别如实说明。
- 遇到阻塞时先检查仍在范围内的可行路径；阻塞状态何时可设置，以当前工具定义为准，不自行规定重试轮数。暂停、恢复、清除和预算变更也只通过当前环境允许的方式进行。
- 用户改变范围时更新可审阅计划，并重新走目标一致性核对；保留仍有效的证据及可获得的连续任务用量记录。
- 验收通过后交付产物、执行过的检查、必要限制及可获取的实际用量。因阻塞或预算停止时交付已完成部分、缺失证据和最小下一步，不降低原验收标准来宣称成功。

- [Using Goals in Codex](https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex)：目标合同、证据验收、先完善草案再激活。

这些链接用于解释机制或核查兼容性；普通引导不需要每轮重新检索。操作时以当前工具契约和已核实的客户端行为为准。
